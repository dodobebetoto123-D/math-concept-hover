Vite + React(JavaScript)로 만든다. **1단계에서는 프로젝트 뼈대 + 06-1 하나만** 기준본 HTML과 똑같이 구현하고 `npm run build` 성공까지 확인한 뒤 보고한다. 나머지 단원은 2단계에서 장별로 확장한다 (순서는 6장 참고). 임의로 디자인을 바꾸지 않는다. 아래 토큰과 규칙이 정답이다.

## 1. 핵심 원칙 (절대 규칙)

1. **조작이 아니라 표시/탐색이다.** 슬라이더, 값 변경 버튼을 넣지 않는다. 교재 그림을 고정으로 띄운다.
2. **인터랙션은 hover 뿐이다.** 선·도형·각에 마우스 커서(mouseenter)를 대면 관련 요소가 동시에 빛나고, 오른쪽 정보 패널이 바뀐다. 모바일 대응으로 click(탭)도 같은 동작을 한다.
3. **커서를 떼도 정보는 유지한다** (mouseleave로 패널을 초기화하지 않는다). 다음 hover가 오면 그때 교체된다.
4. **관계는 양방향으로 묶는다.** 대응변 쌍 중 어느 쪽에 올려도 같은 하이라이트+같은 정보가 뜬다 (예: DE에 올려도, BC에 올려도 동일).
5. **하이라이트는 한 번에 하나만.** 새 hover가 오면 이전 하이라이트를 전부 끄고(clearAll) 새로 적용한다.
6. **판정은 부정까지 명시한다.** 닮음이면 "합동 아님"처럼 아닌 것도 문장에 적는다.

## 2. hover 유형 3가지

| 올리는 곳 | 빛나는 것 | 패널이 알려주는 것 |
|---|---|---|
| 선분 | 그 선 + 대응변/평행한 선 (동시) | 대응변은 무엇인지, 평행인지, 길이의 비 |
| 도형 내부 (면) | 그 도형의 면 전체 (채움+글로우) | 다른 도형과 닮음인지/합동인지/아닌지, 닮음비 |
| 각 표시 (호) | 그 각 + 대응각 (동시) | 대응각은 무엇인지, 왜 같은지 (동위각/공통각 등), 크기 |

선분 hover의 하이라이트는 2층이다: **후광(halo)** — 본선 아래 깔리는 굵은 반투명 선, **본선 색 변경** — 본선 자체의 stroke 색 변경. 부분 대응(전체 변 중 일부만 대응)은 전체는 후광, 대응 부분만 다른 색 후광으로 표시한다 (기준본 AB/AD 방식).

## 4. SVG 레이어 순서 (아래→위, 고정)

1. 도형 면 zone (polygon, fill 투명 평소) — 내부는 이 레이어가 잡는다
2. 후광 레이어 (모든 선분의 halo 복사본)
3. 본선 레이어
4. 평행 표시·각 호 (표시는 평소 숨김/흐림, 해당 관계가 켜질 때만 opacity 1)
5. 꼭짓점 원 + 라벨 텍스트 (pointer-events 없음)
6. **히트 레이어 (맨 위)** — 투명하고 굵은 선(stroke-width 22)과 각 위치의 투명 원. hover/click 판정은 여기서만 받는다. 선이 면보다 위에 있어야 선 hover가 면 hover에 먹히지 않는다.

## 5. 정보 패널

구성: 태그(예: "선분 DE · BC") → 제목 → 본문 → 힌트(고정 문구: 모바일 탭 안내 + "커서를 떼면 마지막 정보 유지").
본문에는 `<b>` 강조와 색 스팬(gold/green/blue) 사용 가능. 문장은 짧고 쉬운 말로, 교재 개념을 그대로 설명한다. 기본 상태(아무것도 안 올렸을 때): 태그 "안내", 제목 "어디든 커서를 올려봐", 본문은 hover 방법 안내.

### 개념 데이터 스키마 (단원 1개 = 객체 1개)

```js
{
  id: '06-1', title: '삼각형에서 평행선 사이의 선분의 길이의 비',
  guide: '선 → 대응변·평행 / 도형 → 닮음·합동 / 각 → 대응각',
  formula: 'BC ∥ DE 이면  AB : AD = AC : AE = BC : DE = 2 : 1',  // 강조 구간은 마크업 허용
  viewBox: '0 0 560 370',
  points: { A:[280,35], B:[100,325], C:[460,325], D:[190,180], E:[370,180] },
  segments: [ { id:'ab', from:'A', to:'B', main:true }, /* … */ ],   // 모든 선분은 halo 생성, main:true 인 것만 본선 표시
  zones:    [ { id:'small', points:['A','D','E'], onClass:'small' }, { id:'trap', points:['D','B','C','E'], onClass:'trap' } ],
  arcs:     [ { id:'b', d:'…' }, /* … */ ],
  marks:    [ { id:'pm-de', points:'280,173 292,180 280,187' }, /* 평행 표시 */ ],
  labels:   [ { x:272, y:24, text:'A', kind:'vertex' }, { x:253, y:172, text:'DE = 4', kind:'side' } ],
  hits:     [ { type:'segment', seg:'ab', key:'ab' }, { type:'circle', cx:128, cy:312, r:20, key:'angB' } ],
  infos: {
    // key = hits의 key 또는 zone id. highlights는 동시에 켤 요소 목록
    de: { highlights: { halos:[['de','GREEN'],['bc','GREEN']], mains:[['de','GREEN'],['bc','GREEN']], marks:['pm-de','pm-bc'] },
          info: { tag:'선분 DE · BC', title:'DE와 BC — 평행 + 대응변', desc:'…' } },
    // bc 키는 de와 같은 내용을 가리킨다 (양방향 묶기)
  }
}
```

구현 메모: highlights 적용 전 clearAll에 해당하는 상태 초기화를 React 상태(activeKey) 하나로 처리한다. 하이라이트는 "지금 active인 key의 highlights만 켜짐"으로 파생시키면 clearAll 버그가 없다.

## 7. 기준 구현 명세 — 06-1 (기준본과 1:1로 맞출 것)

- 좌표: A(280,35) B(100,325) C(460,325) D(190,180) E(370,180), viewBox 0 0 560 370. D·E는 AB·AC의 중점이라 닮음비 1:2.
- 선분: AB, AC, DE, BC가 본선. AD, AE, DB, EC는 후광 전용 (본선은 AB/AC가 겸한다).
- 길이 표기: AD=5, AE=5, AB=10, AC=10 (라벨은 AD/AE만), DE=4, BC=8.
- hover 항목 9개:
  1. 선 DE / 선 BC (공유) — 둘 다 GREEN, 평행 표시 2개 ON. 정보: 평행 + 대응변 + 비 1:2
  2. 선 AB — 본선·후광 GOLD, AD 후광만 BLUE. 정보: 전체 변, 대응은 AD, AD:AB=1:2, AD:DB=1:1
  3. 선 AC — AB와 대칭 (AE가 BLUE)
  4. 각 ∠B — 호 b·d GOLD, DE·BC GREEN 보조. 정보: ∠ADE=∠B 동위각, 약 58°, AA 닮음
  5. 각 ∠C — 호 c·e GOLD. 정보: ∠AED=∠C 동위각, 약 58°
  6. 각 ∠A — 호 a GOLD. 정보: 공통각
  7. 면 △ADE — 면 BLUE 채움, DE 후광 BLUE. 정보: △ADE ∽ △ABC 닮음 (합동 아님), 닮음비 1:2
  8. 면 사다리꼴 DBCE — 면 ORANGE 채움, DE·BC GREEN. 정보: 사다리꼴인 이유 (DE∥BC 한 쌍만), △ABC−△ADE
- 본문 문장은 기준본 HTML의 문장을 그대로 쓴다 (요약·변형 금지).

## 8. 확장 규칙 (2단계, 장별)

- 대상은 `CONCEPTS.md`의 06~11 전 소단원. 우선순위: 06 나머지 → 07 → 08 → 09 → 10 → 11.
- 소단원마다 그림 1개 + hover 항목을 만든다. 관계 종류는 그 단원에 맞게: 대응변/대응각/평행/닮음/합동/넓이 같음/비 일정 등. 색의 의미(3장)는 전 단원에서 바꾸지 않는다.
- 10 경우의 수 / 11 확률은 도형이 아닌 그림(가지 그림 tree, 격자 표, 카드 나열)에도 같은 방식을 적용한다: 칸·가지·카드가 "선/면" 역할을 하고, hover하면 합의 법칙인지 곱의 법칙인지, 순서가 있는지 없는지를 패널이 알려준다. 슬라이더·시뮬레이터 버튼은 넣지 않는다.
- 09-2/09-3 증명 단원은 조각 hover로 각 조각이 무엇과 합동인지를 알려주는 방식으로 한다 (애니메이션 재생 버튼은 넣지 않는다).
- 새 단원을 추가할 때마다 기존 단원의 토큰·컴포넌트를 재사용하고, 단원 전용 CSS를 새로 만들지 않는다.
